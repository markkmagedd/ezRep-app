# Data Model: PR Spotlight Screen

This file expands on the data requirements from the specification.

## 1. Entities

### ExercisePR
Represents the heaviest logged weight for a specific exercise across the user's entire workout history. It is generated by aggregating historical workouts on the client side.

**Fields**:
- `exercise_name` (string): The name of the exercise performed. Used for UI display and alphabetical sorting.
- `weight_kg` (number): The maximum weight lifted for this exercise across all valid completed sets.
- `achieved_at` (Date / ISO string): The timestamp of the workout where this maximum weight was logged. Used to provide context to the user.

**Relationships**:
* Non-persistent derived entity based on `Workout` documents stored in `users/{uid}/workouts`.

## 2. Store Updates (Zustand: `workoutStore.ts`)

We will add a secondary aggregation map to the central `workoutStore` called `exercisePRs` to cache the generated PRs:

```typescript
interface WorkoutState {
  // ... existing fields ...
  exercisePRs: ExercisePR[]; // Array to allow easy array sorting (alphabetical)
  
  // Actions
  loadAllExercisePRs: () => Promise<void>;
}
```

- **`loadAllExercisePRs`**: An async action that pulls all historical workouts (where `ended_at != null`), groups identical `exercise_name` strings, and reduces each group to its maximum `weight_kg` and the most recent `achieved_at` date for that heavy lift.

## 3. Validation Rules

- `weight_kg` MUST be > 0.
- Missing `weight_kg` sets must be ignored in the PR calculations (since some exercises might only track reps).
- Valid PRs must originate from completed sets within a finished workout session.
